# Огляд

ketch встановлює консольні утиліти й застосунки з релізів GitHub на macOS, Linux і Windows.
Здебільшого йому не потрібно від вас нічого, крім назви репозиторію. Ці сторінки
описують випадки, коли потрібно щось іще, і формати, які ви тоді пишете.

## Встановлення

```bash
curl -fsSL https://raw.githubusercontent.com/pyrlyn/ketch/main/install.sh | bash
```

У Windows:

```powershell
irm https://raw.githubusercontent.com/pyrlyn/ketch/main/install.ps1 | iex
```

Потім додайте `~/.ketch/bin` до `PATH` (або `%USERPROFILE%\.ketch\bin` у Windows). `ketch doctor` повідомить, чи це зроблено,
а заразом про все інше, що потребує уваги.

## Щоденне використання

```bash
ketch install pyrlyn/rtok           # будь-який репозиторій, що публікує релізи
ketch install rg                     # або назва, відома реєстру
ketch install sharkdp/fd@v10.2.0     # або точна версія
ketch upgrade                        # усе, що не закріплено
ketch uninstall rg                   # і видалити назад
```

Усе зберігається в `~/.ketch`: версіоновані файли пакетів у `store/`, посилання в
`bin/` і `state.json` із записом про те, що встановлено. Поза цим деревом нічого не
записується, крім бандлів `.app`, місце яких у `/Applications`.

## Як розв'язується назва

Чотири рівні по черзі — перемагає перший, що відповів:

1. ваші власні маніфести в `~/.ketch/manifests/`
2. завантажений реєстр пакетів
3. реєстр, вкомпільований у бінарник, щоб поширені утиліти працювали офлайн
4. виведення з `owner/repo`

Останній рівень і є сенсом ketch: репозиторій, який ніхто не курує, можна встановити
взагалі без маніфесту. Виведення обирає асет релізу, що пасує вашій машині, —
за архітектурою, ОС і libc, — а `ketch info <pkg> --assets` показує кожного
кандидата з отриманою оцінкою та її причиною.
