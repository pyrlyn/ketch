# Обзор

ketch устанавливает консольные утилиты и приложения из релизов GitHub на macOS, Linux и Windows.
Чаще всего ему не нужно от вас ничего, кроме имени репозитория. Эти страницы
описывают случаи, когда нужно что-то ещё, и форматы, которые вы тогда пишете.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/pyrlyn/ketch/main/install.sh | bash
```

В Windows:

```powershell
irm https://raw.githubusercontent.com/pyrlyn/ketch/main/install.ps1 | iex
```

Затем добавьте `~/.ketch/bin` в `PATH` (или `%USERPROFILE%\.ketch\bin` в Windows). `ketch doctor` сообщит, сделано ли это,
а заодно обо всём остальном, что требует внимания.

## Повседневное использование

```bash
ketch install pyrlyn/rtok           # любой репозиторий, публикующий релизы
ketch install rg                     # или имя, известное реестру
ketch install sharkdp/fd@v10.2.0     # или точная версия
ketch upgrade                        # всё, что не закреплено
ketch uninstall rg                   # и удалить обратно
```

Всё хранится в `~/.ketch`: версионированные файлы пакетов в `store/`, ссылки в
`bin/` и `state.json` с записью о том, что установлено. За пределами этого дерева ничего не
пишется, кроме бандлов `.app`, место которых в `/Applications`.

## Как разрешается имя

Четыре уровня по порядку — побеждает первый, который ответил:

1. ваши собственные манифесты в `~/.ketch/manifests/`
2. загруженный реестр пакетов
3. реестр, вкомпилированный в бинарник, чтобы популярные утилиты работали офлайн
4. вывод из `owner/repo`

Последний уровень и есть смысл ketch: репозиторий, который никто не курирует, можно установить
вообще без манифеста. Вывод выбирает ассет релиза, подходящий вашей машине, —
по архитектуре, ОС и libc, — а `ketch info <pkg> --assets` показывает каждого
кандидата с полученной оценкой и её причиной.
